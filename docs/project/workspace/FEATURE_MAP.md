### Key Decisions To Review First

- job-run management is `SYSTEM_ADMIN` only
- action history is visible by unit scope: exact unit for `MANAGER_UNIT:*`, subtree or level-wide
  for `MANAGER_LEVEL`, and all units for `SYSTEM_ADMIN`
- action history is written after the main workflow and retried from compact seed payloads if the
  log write fails
- list views must stay server-paged and filterable by unit/user because logs can grow quickly
- job-run retry actions are explicit admin actions; failed job state is not auto-repaired from list
  reads
- assignment job-run coverage is split between materialize queue rows, queue-scan operation logs,
  notification due-scan operation logs, and Dynamic Form statistic rebuild queue rows
